# 风格校准

当用户提供自己的成稿、改稿、批注或明确偏好时使用。目标是复现用户的选择方式，而不是机械复制词语。

## 样本优先级

从高到低：

1. 用户对本次任务的明确修改意见。
2. 用户确认过的最终稿。
3. 用户主动提供的代表作。
4. 尚未确认的草稿或零散片段。
5. 个人风格内核中的默认值。

样本之间冲突时，优先使用更新、更明确、与当前用途更接近的样本。

## 建立临时风格卡

只提取有证据的维度：

| 维度 | 观察内容 |
| --- | --- |
| 信息密度 | 极简、标准或深入；哪些内容会被删掉 |
| 解释顺序 | 先结论、先场景、先定义或先问题 |
| 句段节奏 | 句子长度、段落长度、列表频率 |
| 标题结构 | 数字层级、问句、结论式标题或无小标题 |
| 术语处理 | 是否保留英文、何时解释、解释到什么程度 |
| 强调方式 | 粗体、引用、表格、代码块的使用习惯 |
| 语气 | 克制、直接、口语化程度、是否保留个人判断 |
| 禁止模式 | 用户反复删除或明确不喜欢的写法 |

没有证据的维度继续使用默认风格，不要凭一个样本臆造完整人格。

## 校准规则

- 模仿结构、取舍和节奏，不复制主题专属句子。
- 不继承事实错误、错别字、隐私信息或不适合当前场景的表达。
- 不因为用户偶尔用了表格、emoji 或长句，就把它升级为固定风格。
- 用户修改了 AI 草稿时，重点观察“删了什么、合并了什么、把什么提前了”。这些选择通常比新增口头词更有价值。
- 风格卡默认只服务当前任务。除非用户明确要求，不修改持久化的个人风格文件。

## 成稿对照

交付前对照样本检查：

1. 信息密度是否接近，而不只是语气相似？
2. 开头和章节顺序是否符合用户的理解路径？
3. 用户常删的套话是否重新出现？
4. 专业词、列表和强调是否使用得同样克制？
5. 如果去掉表面措辞，文章的取舍方式是否仍像用户？

若风格与事实准确性冲突，保留事实并用最接近用户的方式表达，不为模仿而扭曲内容。

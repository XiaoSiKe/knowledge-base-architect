# 内容类型

用于选择知识结构。先判断读者要完成的认知或行动，再选一种主结构；只有交付目标确实同时存在时，才组合两种结构。

## 类型路由

| 内容类型 | 适用目标 | 推荐顺序 |
| --- | --- | --- |
| 概念笔记 | 看懂一个概念并知道边界 | 一句话定义 → 核心机制 → 相近概念区别 → 用途 → 边界 → 相关知识 |
| 对比决策 | 在多个选项中做选择 | 决策问题 → 判断维度 → 证据对比 → 适用情况 → 推荐与代价 |
| 教程 | 从不会到完成第一次操作 | 使用[教程模式](tutorial-mode.md) |
| SOP 或清单 | 稳定重复执行一项工作 | 触发条件 → 前置条件 → 步骤与检查点 → 异常处理 → 完成标准 |
| 多来源综述 | 综合多份资料形成认知 | 核心问题 → 共同结论 → 分歧 → 证据 → 限制 → 待确认问题 |
| 复盘 | 从一次经历中提取以后可用的判断 | 结果 → 已知事实 → 原因 → 有效与无效做法 → 原则 → 后续行动 |
| FAQ | 回答一组高频、独立问题 | 问题 → 一句话答案 → 必要解释 → 相关问题 |
| 发布文章 | 面向外部读者形成完整阅读体验 | 按目标平台适配；知乎使用[知乎模式](zhihu-mode.md) |

## 选择规则

- 用户给出目录时，以用户目录为主，只修复明显缺口。
- 一个主题包含多种内容时，先确定主任务。例如“比较后教我安装”以对比决策为主，在推荐结论后接一条教程路径。
- 不把概念笔记写成操作手册，也不把 SOP 写成长篇科普。
- 表格只用于判断维度稳定、需要横向比较的内容。
- 结构服务于任务闭环，不要求每个栏目都出现。

## 知识库正文与发布文章

知识库正文优先可检索、可更新和可复用：

- 标题直接使用主题或问题；
- 开头写核心结论；
- 将事实、判断、步骤和风险分开；
- 来源、更新时间、标签和相关知识按用户现有系统决定，不默认强加元数据。

发布文章优先连续阅读体验，可以增加必要过渡和叙事，但不能为了流畅隐藏来源分歧或不确定性。

## 拆分与合并

出现以下情况时，建议拆成多篇知识：

- 不同部分解决完全不同的读者任务；
- 某一部分需要独立更新或频繁引用；
- 删除一部分不会影响另一部分理解；
- 合并后标题无法准确概括正文。

出现以下情况时，优先合并：

- 两篇内容回答同一个问题；
- 其中一篇只有上下文，没有独立结论；
- 分开后需要重复大量定义和前置知识。

如果用户只要求一篇成稿，不要擅自创建多篇文件；可以在正文中给出拆分建议。

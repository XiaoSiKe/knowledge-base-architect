# 持久风格档案

只在用户明确要求记住、保存或更新长期写作偏好时使用。普通风格校准继续使用任务内临时风格卡，不产生持久状态。

## 档案格式

优先从 [style-profile.template.json](../assets/style-profile.template.json) 复制一份到用户指定的位置。没有指定位置时先交付建议文件，不擅自写入全局目录。

档案只保存经过确认的表达选择：

- 默认信息密度和内容深度；
- 开头、段落、标题和术语习惯；
- 偏好的内容结构和强调方式；
- 明确不喜欢的写法；
- 适用于特定平台或内容类型的范围；
- 支撑这些判断的样本标识和观察结果。

不要保存原始私密样本、完整聊天记录、个人敏感信息或未经用户确认的推断。

## 创建与更新

1. 从用户确认过的样本或修改意见中提取候选变化。
2. 区分单次偏好、平台偏好和长期默认偏好。
3. 展示将新增、修改和删除的规则；用户已经明确要求执行本次持久化时，无需重复确认同一授权。
4. 基于现有档案更新，不覆盖无关字段。
5. `revision` 增加 1，更新 `updated_at`，并记录简短证据观察。
6. 使用脚本验证：

```bash
python3 scripts/validate_style_profile.py path/to/style-profile.json
```

档案已有版本控制时使用版本历史回滚；没有版本控制时，更新前保留可恢复的上一版。

## 应用顺序

处理风格冲突时依次使用：

1. 用户当前明确要求；
2. 事实、来源、安全和授权边界；
3. 与当前平台或内容类型匹配的档案范围；
4. 档案中的默认范围；
5. 本 Skill 的个人风格内核。

档案缺失某一维度时使用下一级规则，不要自行补齐。档案与新样本冲突时，先按当前任务要求成稿；只有用户要求更新长期偏好时才修改档案。

## 隐私与可移植性

- `evidence` 只记录样本标识和抽象观察，不复制大段原文。
- 档案应当可以被用户阅读、编辑、导出和删除。
- 平台专属偏好放在独立 scope 中，不污染默认风格。
- 验证器只检查结构和安全约束，不能证明档案真的符合用户。

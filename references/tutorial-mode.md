# 教程模式

用于小白科普、入门教程和操作指南。教程的完成标准不是“介绍了所有功能”，而是读者能够建立正确认知并完成一次真实操作。

## 先定义学习结果

写作前明确：

- 读者现在会什么、不会什么；
- 完成教程后能独立做什么；
- 第一次成功的最短路径是什么；
- 哪些风险或前置条件不能省略。

如果标题承诺“完成第一次协作”，正文必须真正带读者完成一次协作，而不是只解释名词。

## 推荐学习顺序

```text
一句话认知 → 必要概念区别 → 第一次成功
→ 解释刚才做了什么 → 常见失败与恢复 → 安全提醒 → 速查
```

这是默认学习路径，不是固定目录。纯概念科普可以省略操作；纯 SOP 可以缩短认知部分。

## 只给一条主路径

第一次操作先选择最稳、依赖最少的一条路径。不要同时展开网页端、命令行、多个工具和全部高级选项。

主路径完成后，再用“如果你使用另一种环境”补充必要分支。分支不能打断第一次成功。

## 步骤写法

关键步骤至少包含：

1. **动作**：读者具体做什么。
2. **结果**：完成后应该看到什么。
3. **恢复**：如果结果不同，先检查什么。

低风险、结果明显的连续动作可以合并，不需要把每一次点击都写成三段。

命令和提示词必须可以直接复制：

- 占位内容使用明确名称，如 `你的用户名`，不要使用含义不明的 `xxx`。
- 说明命令在哪个目录或界面执行。
- 涉及覆盖、删除、公开、付费、上传或权限变更时，保留确认步骤。
- 不把危险命令作为新手默认方案。

## 深度选择

| 深度 | 必须包含 | 可以省略 |
| --- | --- | --- |
| 极简 | 一句话认知、最短步骤、必要风险 | 原理、选项、延伸阅读 |
| 标准 | 认知、区别、主路径、预期结果、常见问题、速查 | 边缘功能和完整历史 |
| 深入 | 标准内容、原理、选择依据、失败恢复、下一阶段 | 与当前目标无关的功能枚举 |

深入不等于堆功能。新增一节前先判断它是否帮助理解、行动、排错或安全。

## 教程验收

- 标题承诺的结果在正文中有对应步骤。
- 新术语第一次出现时已经解释。
- 读者不需要先掌握未讲过的知识。
- 每条主路径都有明确终点。
- 最常见的一个到三个失败有恢复办法。
- 结尾留下的是流程、速查或下一步，不是空泛总结。
